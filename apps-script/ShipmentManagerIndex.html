Backfill Historical Data (Admin)
▾
One-time (or occasional) import for older dates. Paste the wide warehouse-blocks-with-date-columns data into a tab named exactly SNAPSHOT_BACKFILL_RAW in this spreadsheet (regular paste - let Sheets auto-split it into columns), then run this. By default this only replaces the dates found in the pasted data. Check the box below to wipe the entire log first - use that after a parsing fix, since a normal re-run can't clean up dates an earlier attempt mis-labeled.
Check for Suspicious Zero-Stock (Admin)
▾
Scans the entire logged history for any SKU × warehouse that reads 0 stock for its most recent 3+ uploaded dates in a row, right after a meaningfully positive reading - the same pattern reported for TR-2460-Sky-Blue @ Faridabad. This only looks for the pattern in already-logged data; it can't tell a genuine stockout apart from a bad import, so treat it as a "go double-check these against the source file" list, not a confirmed bug list.
Manage Warehouses & SKUs (Admin)
▾
Disable a warehouse or SKU to hide it from the Snapshot grid and search everywhere until you re-enable it. The underlying logged data isn't touched - only what's shown.
Add a Warehouse or Item ID That Hasn't Shipped Yet
For a warehouse or Item ID that genuinely exists but hasn't appeared in an export - e.g. a warehouse just onboarded with nothing sent to it, or an Item ID never shipped to a particular warehouse. Enter the Blinkit Item ID(s) - the SKU is picked up automatically from the SKU Master, so only the SKU ever shows in the grid, not the raw Item ID. Adds each with 0 stock so it's visible ahead of the first real upload; once it shows up in an export, real numbers take over automatically. For a brand-new warehouse, enter several Item IDs at once (one per line, or comma-separated). This only adds the warehouse to this Snapshot grid - if you'll also be creating shipments to/from it, add it separately in the Warehouses tab (different, unrelated setup: GST, Consignee, platform tagging).

An invoice number is permanently blocked from reuse once it's edited away from a shipment that's still active - this prevents two different documents ever sharing one number. A number freed up by simply deleting a shipment already doesn't need restoring and won't show up here. Restore only if you're sure the original document was never actually finalized under this number.
